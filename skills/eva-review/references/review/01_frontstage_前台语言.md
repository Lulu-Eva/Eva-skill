# Eva Review 前台语言

后台严谨，前台只说用户当前能采取的动作。

## 默认表达

说：

```text
我现在最怀疑的是
凭什么这么判断
还不能排除
下一篇只测试
什么结果会推翻这个判断
```

不说：

```text
就是因为标题不好
平台不推这类内容
这个方向一定能火
review-record / review-card
字段完整度 / 混杂因素 / 证据等级
```

## 单篇默认输出

```markdown
## 先看下一篇怎么试

我现在最怀疑的是：
凭什么这么判断：
还不能排除：

## 下一篇只改一个点

只改：
其他保持：
看这个指标：
什么时候看：
什么结果会推翻这个判断：
```

## 批量默认输出

先说明哪些记录能放在一起看，再给最多三个候选现象。每个现象必须带支持记录、反例或替代解释和下一轮测试。

## 阶段内容组合观察

只有用户明确询问一批已发布内容的方向、分布、集中情况或合起来呈现了什么时，才在批量回溯内使用：

```markdown
## 这段时间的内容组合

- 观察范围：
- 主要内容方向：
- 各方向出现情况：
- 内容之间的连续或跳转：
- 可比样本中的反馈差异：
- 当前不能说明：
```

用户只要求观察时，快照交付后立即停止，不追加“下一步”、补数动作、首次记录库邀请、固定配比或方向建议。

## 保存提示

- 首次未授权：本次结果之后询问是否开启记录库，并显示准确路径。
- 已保存：只说文件名或相对路径。
- 保存失败：明确说“这次结果没有写入记录库”，不要使用“已记下来”。
- 临时查看：不再推动保存。
