# Eva-skill 低置信度授权协议

本文件是标题未验证、素材不足、Brief 不完整时是否允许继续试结构的唯一真源。

低置信度不是省略流程的入口，也不是代写许可。它默认只输出路线图、段落槽位和素材占位，不能包装成可发布终稿。

## 授权门槛

用户坚持先做时，不要求用户复述后台术语；只要用户明确要先看草稿，就允许进入未验证草稿流程。

未验证草稿的后台边界必须同时满足：

1. 用户知道标题、数据、Brief 或素材尚未验证/补齐。
2. 当前输出只是草稿框架或占位草案。
3. 用户知道不能直接当最终稿发布。

以下自然表达直接视为允许先出未验证草稿：

- “先写一版。”
- “先来一版。”
- “先搭个草稿。”
- “先给我个草稿。”
- “不用管数据，你先写吧。”
- “你先写吧，后面我再改。”
- “不管验证，先出一版。”
- “先按现有材料写。”
- “我知道没验证，先试结构。”
- “我知道没验证，先低置信度试结构。”

前台不要要求用户说“低置信度”“授权”“结构试验”等工程词。

## 标题链路

标题无验证时，默认不进入 `/eva-script`。只允许：

1. 输出爆款标题搜索方案，让用户贴回候选标题。
2. 用户明确要先看草稿后，输出后台低置信度标题交接卡。

低置信度标题交接卡是后台字段，不默认外显；需要展示字段时才写：

```text
标题来源：低置信度试结构
标题验证状态：未验证-用户授权试结构
成稿置信度上限：低
```

后续正文逻辑链推理、正文路线图和正文撰写的成稿置信度不得超过“低”。

## 正文链路

未验证草稿仍然必须按主链路走：

```text
交接卡
-> 正文逻辑链推理
-> 正文路线图
-> 正文撰写
```

如果结构都立不住，不输出完整草案。缺素材、经历、数据、评论区原话、真实使用感受的位置必须用占位符，不得补写成真实内容。

只有同时满足以下条件，才允许进入正文撰写输出带占位符草案：

1. 用户已经提供足够真实素材或原稿。
2. 用户明确要求先写一版、先搭草稿或按现有材料整理成占位草案。
3. 正文路线图已经输出低置信度正文路线图。

否则默认停在路线图、段落槽位和待补素材清单。

开头必须标注：

```text
我先给你一版没经过验证的草稿，先看结构和表达，别直接发。要发之前还需要再补标题、人群或真实素材验证。
```

## 商单链路

只有产品名和几个卖点、没有正式 Brief 时，可以做低置信度卖点拆解，但不得输出正式商单约束卡。

商单内容任务卡里的“学员可用素材”为未提供类、未命中类或未扫描类时，统一按低置信度处理。具体状态以 `references/shared/01_asset-state_资产状态归一表.md` 和 `references/shared/03_commercial-constraint-card_商单约束卡真源.md` 为准。

- 不进入高置信度正文成稿。
- 使用感受、经历、效果、反馈位置必须标注 `[待补充真实使用感受]`。
- 不得编造体验、数据、反馈或效果承诺。
