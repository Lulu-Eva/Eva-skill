# Eva 账号定位暂停恢复与可选持久化

账号定位可能跨越搜索、发布和等待反馈。默认只在当前对话继续；用户明确同意后，才把最小状态写入当前项目。

## 保存邀请

出现以下情况，可以在交付暂停摘要后只邀请一次保存：

- 已提取个人材料方向并布置下一步平台取证；
- 已形成至少一个候选与下一验证；
- 用户要离开去搜索、发布或等待数据；
- 用户明确说“保存进度、下次继续、给我建档”；
- 材料很长，重复讲述成本明显。

推荐问法：

> 这轮已经形成可恢复的定位进度和下一步，但目前还没有写入项目。要不要保存，等你带回搜索或发布反馈后继续？

用户拒绝后本轮不再邀请。用户已明确授权保存时不重复询问；包含收入、健康、家庭、工作单位、客户或未公开产品等敏感信息时，仍需单独确认隐私范围。

## 保存边界

- 保存位置固定在当前项目 `./eva-positioning/`，不写入 Skill 源码、全局目录或其他项目。
- 如果当前目录就是 Eva-skill 源码、安装目录或发行包，先让用户指定真实业务项目目录；不得把定位状态写进 Skill 本体。源码仓库的 `.gitignore` 只是最后一道防误提交保护，不构成保存授权。
- 不扫描电脑寻找历史定位；只有用户明确恢复时才读取该目录。
- 不跟随逃出 `./eva-positioning/` 的符号链接。
- 不保存第三方截图正文、客户名单、联系方式、平台 Cookie、账号密码或原始私密文件。
- 证据只保存必要摘要、来源类型、时间、相对路径或用户提供的来源标识。
- 不建立新的 Eva Asset，不改写 Memory、Learn 或 Review 的数据契约。
- 状态文件只帮助恢复判断，不等于定位结论已经成立。

## 目录与文件

```text
./eva-positioning/
└── <profile-id>/
    ├── state-v001.md
    ├── state-v002.md
    └── ...
```

- `profile-id` 只能使用字母、数字、点、下划线和连字符，首字符必须是字母或数字；不能从隐私内容生成。
- 每次更新新增 `state-vNNN.md`，不覆盖旧版本。
- 同一账号沿用同一个 `profile-id`；多个账号分别建档。
- 无法判断用户指哪个账号时，只问一次，不自动混合。

## 最小状态格式

```markdown
---
eva_positioning_state: true
eva_version: 2.4.2
profile_id: example-account
revision: 1
created_at: 2026-08-24T00:00:00+08:00
stage: material-direction
privacy_confirmed: false
---
```

`stage` 按当前权限写为 `material-direction / candidate / working / deep-complete`；不得把尚未取得平台证据的个人材料方向写成 `candidate`。

`revision: 1` 不写 `supersedes`。从第二版开始，frontmatter 必须增加上一版在同一 `profile-id` 目录内的相对文件名，例如：

```yaml
revision: 2
supersedes: state-v001.md
```

`supersedes` 不得写绝对路径，不得跨出当前 `profile-id`，并且目标文件必须存在且可解析。出现分叉或父版本缺失时先停止更新，只问一次让用户选择，不自动猜测父链。

保存前先预览将写入的摘要，得到用户确认后写入新版本。工具允许时先写临时文件、校验 frontmatter 与正文均可读，再原子改名；失败时明确说明没有保存成功，不声称已建档。

## 恢复流程

用户说“继续上次账号定位”时：

1. 只扫描当前项目 `./eva-positioning/` 中带 `eva_positioning_state: true` 的 Markdown；
2. 没有档案时说明尚未保存，继续使用当前对话材料；
3. 一个账号时读取 revision 最大且可解析的文件；
4. 多个账号时只列出账号标识和最近更新时间，问一次选择；
5. 读取用户本轮带回的是问题回答、平台证据、发布反馈还是目标变化；
6. 更新证据与候选，再重新选择唯一下一动作；
7. 不机械延续暂停前的问题，新材料可能已经让旧问题失效。

### 2.4.1 进度兼容

- 恢复 `eva_version: 2.4.1` 的 L1 时，先重新检查其候选是否已有最低限度的合格平台证据。
- 有合格证据时，保留候选并按新 L1 继续；没有时，保留原始事实、反证和公开边界，但把运行权限降回 L0，将原候选改称为“个人材料方向”并布置取证。
- 这是恢复时的内部解释，不覆盖或回写旧档案。用户后续明确确认保存时，才按新版本链生成一份新状态。

损坏文件单独报告，不因此读取更广目录；存在分叉版本或 revision 冲突时只问一次，不自动猜测。

## 删除与导出

- 本入口不自动删除、合并或归档旧状态。
- 用户明确要求删除时，先列出将删除的相对路径并再次确认。
- `./eva-positioning/` 作为 Positioning 独立数据域纳入 Eva 统一数据备份，不并入 Memory：`memory` 范围不包含定位状态，`complete` 默认包含，`custom` 可由用户选择包含或排除。
- 导出前预览只显示账号档案数、正式状态文件数、总文件数与体积、待校验或损坏状态数以及安全跳过项，不展示状态正文、证据摘要或绝对源路径。
- 可安全读取但 frontmatter 不完整或无法解析的状态仍纳入备份并标记待校验或损坏；不可读的计划内普通文件使整次导出失败。
- 完整数据包是本地未加密 ZIP，可能包含账号经营目标、平台证据摘要和未公开业务事实；生成前必须明确提醒用户妥善保管。
- 新生成的包使用备份格式 v2；历史 v1 完整包仍按 Memory、Learn 和 Review 验证，不因缺少 Positioning 而失效。
- 统一备份流程不自动解压或恢复。用户手动将 `eva-positioning/` 放回目标项目后才按上述恢复流程读取；目标已有同名账号档案或同版本状态时先停止，不自动覆盖或合并。
