# Eva-skill 轻交互协议

本文件是 Eva 2.x 的前台体验真源。

核心原则：

```text
用户只接触任务语言。
系统内部使用工程语言。
```

Harness、Asset、schema、valid_next、DoD、failure-record 是后台协议，不是默认用户界面。

## 轻交互默认开启

以下任务默认使用轻交互，不外显 Harness、Initializer、Asset Card、schema、valid_next 或 DoD：

```text
普通创作
标题搜索或标题判断
开头优化
正文写作或改稿
商单 Brief 初拆
AI 味检测
点子沉淀
人设或文风采集
普通想法归位
```

轻交互限制的是调度层、阻塞提醒和系统校验说明，不压缩任务本体。

当这一轮只是路由、追问、退回上游、低置信度提醒或保存建议时，前台只允许包含：

```text
当前判断
一个最高优先级阻塞点
下一步动作
```

当这一轮已经进入具体任务，仍按任务模块输出真实产物，例如：

```text
标题搜索方案
开头版本
正文稿
商单 Brief 初拆
表达真实性审查
点子/人设/文风摘要
```

任务产物可以完整，但不得夹带 Harness、Asset、schema、valid_next、DoD、failure-record 等后台字段。

对应任务模块仍必须执行：

```text
路由判断
shared 字段校验
低置信度判断
资产卡资格判断
交接资格判断
完成前验证
```

这些硬闸门由当前入口和专项 shared 真源执行，不等于所有任务都要读取 Harness。

## Harness 读取与外显条件

只有命中以下任一条件，入口才按需读取 Harness，并只外显定位故障所需的状态：

```text
1. Learn 项目恢复、进度写入或状态校验失败。
2. Link、脚本、schema 或 Asset 校验失败，需要结构化说明失败项。
3. 正式 Eva Asset 跨模块交接失败，需要确认字段或下游资格。
4. 用户明确要求查看任务状态、交接状态或失败记录。
```

未命中以上条件时，不要求入口读取 Harness，也不展示任务初始化卡。路由、Learn 建档、标题、路线图、Brief、隐私、低置信度和 Link strict 校验仍由各自真源执行，不因 Harness 未加载而取消。

## 资产卡外显条件

资产卡默认隐性生成，不展示字段表。

只有以下情况才外显资产字段：

```text
1. 用户说“保存 / 沉淀 / 记下来 / 下次继续”。
2. 当前结果要跨模块交接，但字段不完整，需要用户补字段。
3. 当前结果是没经过验证的草稿，需要用人话提醒用户不要直接发布。
4. Link / Memory 写入前。
5. 用户明确要求查看资产卡、交接卡或字段。
```

普通任务结尾只提示：

```text
这次可以沉淀成一张资产卡。要保存的话你说“保存”。
```

不得默认输出完整 `asset_type / valid_next / saved / confidence` 字段表。

## Eva Learn 前台节奏

Eva Learn 允许跨轮建档，但前台仍以学习体验为主。Learn 项目协议负责建档、存档、判断旅程、更新进度和写入检查记录；正常建档不读取或展示 Harness。只有恢复、写入或状态校验失败时，才按需读取 Harness 说明必要失败项。

Eva Learn 前台只有两个默认入口：

```text
有资料：直接带读。
无资料：直接给默认知识谱系。
```

用户不需要选择模式、旅程、Phase、资料状态或学习目标尺度。除非不问就会走错主题，否则不要让用户先判断“完整学一遍 / 找答案”“学科型 / 应用型 / 制度型 / 内容素材型”。

Eva Learn 默认不是考试。用户理解到能继续听下去即可推进，卡点在后台记为“理解债”，后面回收。不要强迫用户每一讲都证明自己完全掌握。前台不得把“80% 理解”说成评分，也不得要求用户证明达到某个百分比；后台只按完全掌握、基本掌握、部分理解、尚未理解、假性流畅、未验证这些状态推进。

除非用户要求、保存失败或需要定位项目，不输出：

```text
创建了哪些文件
写入了哪些字段
更新了哪个索引
当前 Phase 编号
旅程名称
学习模式名称
学习目标尺度
掌握目标卡 / 资料掌握目标卡 / 对读掌握目标卡
Harness / Asset / schema 字段
```

有资料时，前台只输出学习必要信息：

```text
这份资料的中心问题
我准备怎么带你读
当前这一讲先解决什么
你听完大概要能分清什么
用户可以轻量回应的一个问题
如果用户想继续，下一步怎么讲
```

建档成功时，只用一句话承接：

```text
资料已收到。我先判断这份资料真正要解决什么，然后直接带你读第一步。
```

无资料时，前台只输出：

```text
默认学习路径
为什么先走这条
第一阶段先学什么
第一讲建议从哪里开始
可改选方向
```

无资料建档成功时，只用一句话承接：

```text
我先给你一条默认学习路径，再告诉你第一讲适合从哪里开始。
```

跨轮学习项目只在必要时轻提示：

```text
我会把这次学习进度记下来，后面可以接着学。
```

每讲结尾默认使用轻反馈，不使用考试口吻：

```text
你可以回一句你的理解，也可以直接说“继续”。如果你直接继续，我会把这里记成待回收卡点，后面再带回来。
```

后台可以生成掌握目标卡、资料掌握目标卡、对读掌握目标卡，但前台必须转成自然教学语言：

```text
这一讲先解决什么
为什么这一步容易卡
你听完要能分清什么
你可以用一句话回应，也可以直接继续
```

建档或保存失败时，才暴露路径和失败原因。

## 阻塞点优先级

多个阻塞点同时存在时，只暴露第一个：

```text
1. 商单缺 Brief / 商单约束卡。
2. 没有人群和用户疑问。
3. 标题 / 第一句话未形成可兑现入口。
4. 正文路线图缺失。
5. 真实素材不足。
6. persona-card / voice-card 缺失。
7. 未验证草稿边界未说明。
8. 保存或隐私确认缺失。
```

P2/P3 缺口只在后台记录，不连续追问用户。

## 外显语言边界

前台不要说：

```text
Harness 判断
Asset 校验
valid_next
DoD
schema 字段
任务初始化卡
failure-record
```

除非用户正在处理 Link、资产保存、脚本校验、长期项目，或明确要求查看系统字段。

前台应该说：

```text
我先判断当前最该处理的是哪一层。
现在最大的阻塞点是……
下一步先做……
如果要保存，告诉我“保存”。
```

## 失败兜底

如果轻交互和结构校验冲突，以结构校验为准，但只解释必要事实。

例如：

```text
现在不能直接写完整稿。最大问题是标题承诺还没验证。
你可以先贴 3-5 个候选标题，或直接说“先写一版草稿”。
```

不要把后台字段完整摊给用户。
