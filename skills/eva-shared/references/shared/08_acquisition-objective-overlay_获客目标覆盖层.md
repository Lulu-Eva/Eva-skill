# Eva 信任累积型获客覆盖层

本文件是 Eva-skill `2.3.0` 的获客能力真源。它只在用户明确要通过短视频获得客户咨询、建立购买信任、推动潜在客户采取现实行动，或规划一组获客短视频时加载；普通思考、普通创作、涨粉、爆款和 Article 生产不得加载。

它不是新入口、定位系统、销售系统或第二套写稿模板。它只把 Eva 已有的 Audience、Product Service、Persona、Title、Opening、Script、Preflight 和 Review 组织成一条按需链路：

> 获客不是用一条内容说服别人购买，而是用多条内容反复证明：我理解你的处境，我的判断有根据，我会兑现内容承诺，我不会夸大产品能力。

内部执行句是：**一题一证，逐条守诺，发布后求证。** 不必把这句话机械展示给用户。

## 一、进入与退出

明确出现以下任一目标时进入：

- 写一条或一组获客短视频。
- 获得更精准的客户咨询。
- 为自己真实提供的产品或服务建立购买信任。
- 通过内容帮助潜在客户判断是否适合采取下一步行动。

以下信号本身不足以进入：涨粉、扩大受众、做爆款、提高播放、做账号、打造 IP、账号定位、赛道定位。

用户明确要“整理、记住、沉淀、保存或以后复用”自己的产品与服务事实时，即使提到“以后做获客内容”，也先完成 Product Service 采集，不加载本覆盖层。仅说“以后围绕这项业务做获客内容”不构成采集或保存授权；若既没有事实沉淀动作，也没有现在写稿、规划几条或做矩阵的动作，只问一次：用户想先建立可复用底稿，还是现在写或规划获客内容。用户选择后再进入 Product Service、Create 或 Think。

用户把“扩大受众”和“获得客户咨询”混在一起，且二者会改变内容任务时，只问一次：

> 你这次更希望扩大内容受众，还是获得对产品真正有需求的客户咨询？

用户没有获客意图，或明确改回普通表达、观点、故事和经验内容时，立即退出本覆盖层，继续原模块，不保留隐性营销目标。

## 二、最小现实判断

不要先展示商业问卷。只在后台确认完成当前内容真正需要的几件事：

- 用户真实提供什么产品或服务，以及交付前后能够被用户观察到的真实差异。
- 这条内容替哪一种具体处境中的人，回答哪一个真实问题。
- 这个人此刻还不确定什么；本条内容只推进其中哪一个信任判断。
- 用户已经提供什么可信依据：真实处境、亲历、选择与代价、工作过程、样本观察、可核验事实或有边界的逻辑推导。
- 当前判断与产品各自适用到哪里、不能推出什么。
- 是否存在一个用户已确认、现实中真实可执行的下一步动作。

这些不是固定字段表，也没有必须依次填写的顺序。所有判断只能处于三种证据状态：`用户明确确认`、`现有材料足以支持的推论`、`尚待真实反馈验证`。信息足够时直接继续，不为了填满清单而追问。

缺口处理固定为：

1. 用户明确要获客，但没有说清真实产品或服务：只问它是什么、实际能解决什么。
2. 产品清楚，但具体人群、认知缺口或用户问题不清：按需调用 Audience Finder，完成后返回原调用者。
3. 没有可信依据：仍可交付有价值的观点或方法，但不能编造成果、资格、案例、客户反馈或产品效果。
4. 没有真实行动入口：可以停在理解、判断、资格或边界，不补造私信、加微信、领资料或购买动作。

### 产品与服务底稿的按需回捞

`product-service-card` 不是获客创作的强制前置。只在本覆盖层已经命中时，按以下优先级使用：

```text
当前对话中用户明确确认的事实
> 用户点名的产品与服务底稿
> 唯一明确匹配的最新 active 底稿
> 多个候选时只问一次
> 没有可用底稿时沿用当前会话最小商业上下文
```

只有同 `profile_id` 的版本链无分叉、最新版明确且为 `active` 时才能默认回捞；`paused` 和 `retired` 不得回退到旧 `active` 版使用。用户显式点名最新 `paused` 底稿时，可以只读使用其中仍有效的能力、方法、依据和边界，但必须保留暂停状态，不得生成承接入口；只有用户要求现实承接动作时，才确认是否已经恢复承接。最新 `retired` 底稿只能作为历史材料，不得证明当前仍在提供；只有本轮重新确认的现实事实才能建立当前提供关系。一条内容只用一项底稿，不混用多张卡的能力、案例、价格、行动入口或边界。本轮新事实优先；先完成任务，再邀请用户是否更新底稿。

用户在本轮主动、明确给出的价格、名额、开放状态、时限和行动入口，已经完成本轮确认；只有这些时效性事实仅来自历史底稿、推断或含糊材料时，写入正文前才重新确认。底稿存在只表示事实可按需调用，不等于必须植入产品，也不等于 CTA 授权。底稿的“适合谁”不替代 Audience Finder 对传播人群的判断。详细采集、保存和版本规则只读取 `../eva-shared/references/memory/04_eva-product-service_产品与服务采集.md`。

## 三、传播人群不等于可承接客户

Audience Finder 继续负责话题层的具体人群、认知缺口和用户问题。本覆盖层只追加一次现实判断：

```text
会被这个话题打动的人
≠ 一定适合当前产品的人
≠ 已经准备采取行动的人
```

不得把泛共鸣人群自动写成付费客户，也不得为了筛选客户而抹掉话题本身的公共价值。没有充分依据时，把“产品是否适合这群人”保留为尚待验证，不使用要求购买的内容结论。

## 四、单条短视频内容合同

一条内容只推进一个尚未完成的信任判断，而不是同时塞入拉新、教育、证明和成交。按当前真实缺口选择一项：

- **被理解**：用户是否相信创作者真的说准了自己的具体处境。
- **有判断**：用户是否相信这不是空泛口号，而是一个有依据的解释。
- **有资格**：用户是否理解创作者为什么有资格讲这件事。
- **守边界**：用户是否知道判断或产品能解决什么、不能解决什么。
- **交付可信**：用户是否能从真实方法、工作过程或有边界的结果中，判断创作者或产品确实能做它声称的事。
- **可行动**：条件成熟时，用户是否知道一个真实且与当前内容相称的下一步。

六个名称只用于后台归类，不能直接充当本条内容的信任判断或矩阵选题。只写“建立专业信任”“增强价值感”“提高交付可信”或“让用户觉得被理解”，都视为信任判断尚未形成。

一个可以进入创作的信任判断必须具体到：哪一种具体处境中的人，围绕当前真实用户问题，仍不能确认哪一件具体事情。内部只需收束成一句：

> 对「{具体处境中的具体人群}」，本条帮助他判断：「{围绕真实用户问题、目前仍不确定的一件具体事情}」。

这句话只在后台使用，不展示成问卷，也不新增字段。它必须与一项能够直接回应这件事的可信依据相连，并沿用上文三种证据状态；必要边界要说明该依据仍不能推出什么。只有材料确实支持时，才可以写“已经相信 A、但仍不能确认 B”，不得替客户假设已经接受的前提。没有可信依据时，可以交付有边界的观点或方法，但不能把它包装成已经得到证明的信任结论。

上下文足够时直接形成，不增加追问。只有两种具体判断会导向明显不同的内容主线、现有材料又无法区分时，才沿用轻交互规则问一个决定性问题；不得为了把句子填完整而猜测人群、疑问、信任判断或依据。

以上不是固定漏斗，也不要求每条全部出现。无论本条选择哪一个信任判断，标题或第一句话的内容承诺都必须在正文中完整兑现；这是 Eva 的通用写作硬约束，不是可选的获客任务。单条短视频只需形成一份内容合同，顺序服从内容：

1. 一个真实用户问题。
2. 一个已经具体到人群、处境和一件尚未确定之事的信任判断。
3. 一个核心判断。
4. 一个能够承担解释或证明作用的可信依据。
5. 一个必要的适用边界。
6. 对标题或第一句话的一次完整兑现。

不同内容可以使用 Eva 原有路线：

- 故事：处境、经历、判断和必要边界。
- 观点：判断、解释、依据和必要边界。
- 方法：问题、具体动作、中间结果和完成判断。
- 产品解释：常见误解、能解决什么、不能解决什么、适合与不适合谁。

这不是六段式模板。Create 仍由原有 Title、Opening 和 Script 决定前台结构。Persona 也不是每条内容的硬闸门；只有本条需要证明“为什么由你来说”，且现有材料又不足时，才按需读取或回捞真实人设素材。

CTA 是可选项。只有行动真实存在、与本条信任判断相称，并且用户已经授权时才可写入。内容目标不能覆盖平台、标题、第一句话、Brief、事实边界或用户真正要回答的问题。

## 五、信任缺口与内容矩阵

只有用户明确说“规划一组、一个系列、内容矩阵”时，才使用信任缺口图安排多条内容。

矩阵是上游问题与证据规划，不等于已经进入具体标题或成稿。即使用户说“规划短视频矩阵”，也先留在 Think；平台尚未指定时不追问，等用户选中某一条并要求制作标题、开头或正文时，再由 Create 确认平台并进入对应硬闸门。

矩阵规则：

1. 先列出客户仍未解决的真实问题，而不是先套购买漏斗。
2. 判断每个问题主要对应哪一个信任缺口。
   六类名称只能辅助归类，不能直接作为矩阵选题；每条仍要落到具体人群、具体处境、真实用户问题和一件尚未确定的具体事情。
3. 每条只回答一个问题、增加一个新的可信依据。
4. 同一个判断再次出现时必须增加新证据，不能换皮重复卖点。
5. 每条都能独立成立，不能假设用户按顺序看到。
6. 篇数、比例和发布顺序服从当前事实，不套固定配比。
7. 每条都必须提供完整价值，不能故意藏住关键答案制造咨询。
8. 下一条根据真实反馈调整，不机械进入“漏斗下一阶段”。

信任累积不是数量累积，而是用户一次次看到同一套可信纪律：说准处境、判断有据、资格真实、承诺兑现、边界清楚。

矩阵是当前会话的规划结果，不自动生成定位卡、获客卡、客户卡、信任卡或长期商业档案；只有用户明确进入产品与服务采集，完整底稿已经成立并确认保存时，才允许写入 `product-service-card`。

## 六、与现有模块的关系

跨模块选路、同轮接力与停点只读取同目录 `07_next-step-navigation_动态选路与下一步推荐.md`；本文件只提供获客业务闸门，不维护第二套导航。

- Think：每次只补一个决定性缺口；不输出完整账号、产品或人设定位报告。
- Audience Finder：继续判断话题戳中谁，不改造成付费客户画像器，内部调用后返回原模块。
- Create：获客短视频仍以平台、Title、Opening、Script、Brief 和真实素材真源为准。本覆盖层只能排序素材并增加可信边界，不能建立第二套写稿方法或绕过硬闸门。
- Product Service、Persona 与 Memory：Product Service 只在明确获客任务按需提供可承接问题、实际帮助、能力依据和边界；Persona 只按需提供真实经历、选择代价、长期判断和表达资格。两者不可混用，都不自动保存。
- Brief：品牌付费合作仍先进入 Brief；自有产品获客目标不能替代商单约束。
- Preflight：只读使用下方一致性检查，最终三档和早停仍归 Preflight 主控，不补 CTA，不生成销售话术。
- Review：只在内容已经发布且用户给出真实反馈时，沿用现有可证伪复盘；不建立线索系统，不把单篇结果升级成账号规律。

Create 的 Article 生产不读取本文件，也不扫描 `product-service-card`；文章沿用自身读者认知任务、论证链以及原生事实、证据、产品和 CTA 边界。待发文章明确包含产品承诺或行动入口时，Preflight 仍可按下节只读审核。

## 七、Preflight 四重一致性

只有待审稿明确以获客为目标，或包含产品承诺、咨询/购买动作时加载。除原有 Preflight 判断外，只追加：

1. **人群一致性**：被话题打动的人与产品真实能承接的人，是否被混为一谈。
2. **资格一致性**：作者声称的经历、判断、成果和能力，是否有用户材料支持。
3. **内容一致性**：标题、第一句话、正文和结尾，是否在回答同一个真实问题并完成承诺。
4. **能力一致性**：正文的产品承诺，是否超过产品能力、案例证据或现实行动入口。

只核对稿件已经写出的能力、依据、边界和行动入口。没有产品名或 CTA 不是不通过理由；卡片未记录某项事实只表示当前无卡片证据，不得直接推断现实中不存在。虚构产品效果、客户成果、身份资格或现实行动入口属于发布级阻塞；明确声称超出已有真实依据与边界时，按事实/承诺问题处理。产品出现生硬但不构成事实或承诺问题时，通常只属于优化建议。严重度汇总、三档结论和唯一下一步仍由 Preflight 主控决定。

## 八、Review 发布后求证

只有用户提供已经发布的内容和真实反馈，且明确要复盘获客内容时，才把本条原先的信任判断作为一个待验证假设：

```text
本条原本想推进什么信任判断
→ 用户实际提供了什么反馈
→ 还有哪些竞争解释
→ 下一条只改一个变量
→ 什么结果会推翻当前判断
```

不得把收藏、评论、咨询或成交中的任何单一指标自动等同于“信任”。没有分母不算率，没有真实咨询或成交数据就不评价咨询和成交；单篇结果永远不能直接升级成账号长期规律。

允许为验证当前假设，询问去身份化的汇总事实，例如“3个咨询者中有几个符合这次定义的目标处境”；这不是给个人线索打分，不能收集身份、逐人评级、保存名单或据此自动跟进。样本很少时只作描述性核对，不计算所谓精准率，不升级成长期方向。没有标题、逐字稿或完整内容时，只能判断用户反馈是否支持当前假设，不能归因到标题、开头或正文。

## 九、绝对边界

- 不自动搜索平台、竞品或市场数据，不绕过小红书标题验证。
- 抖音、视频号继续走无标题第一句话链路，不强制标题搜索。
- 不编造需求、案例、收入、效果、教程、产品能力、客户反馈或线索数据。
- 真实经历只做相关性筛选，不改变事实含义，不为了成交抹掉与判断相关的失败、限制或转折。
- 第三方反馈必须来自用户提供的真实材料；不生成仿真评论、伪造客户口吻或把匿名反馈包装成实名证言。
- 不因信息不足而按行业常识补齐产品、客户或信任缺口。
- 不默认生成评论关键词、私信、加微信、社群、稀缺、优惠或焦虑型 CTA。
- 不制造敌人、身份焦虑或情绪操控来换取咨询。
- 不预测播放、咨询、线索、成交或转化区间。
- 不进入评论区线索识别、私信回复、线索评分、谈单、成交、CRM 或私域运营。
- 不复制第三方提示词、文案、案例、固定分类、专有命名、代码或人物表达。
- 不新增一级 Skill 或 handoff target。获客流程不得自动生成长期商业档案；只有用户明确进入产品与服务采集，底稿成立且确认保存时，才允许生成 `product-service-card`。

完成当前创作、审核或复盘后停止。用户另行提出发布后的销售承接任务时，明确说明该获客能力不具备销售系统，不能冒充已经完成线索或成交判断。
