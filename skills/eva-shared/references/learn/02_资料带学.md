# Eva Learn 02：资料带学

适用场景：用户提供一份或少量资料，想完整学懂，或带着具体问题从资料中找答案。

本文件是一条线性旅程：

```text
资料存档 -> 意图判断 -> 教学决策 -> 学习目录 -> 单讲带读 -> 掌握检查 -> 教学调整 -> 沉淀 -> 完成判断
```

进入本文件前必须已经建档。若未建档，返回 `references/learn/00_eva-learn.md`，不得继续。

单份或少量资料允许从最小档案开始。第一讲前只创建 `00-学习进度.md` 项目锚点；第一讲内容形成后、展示给用户前，再创建并写入 `07-学习问答原稿.md`、`sources/INDEX.md` 和 `sources/原始资料/`。其余记录按 `05_eva-learn-project_分级建档与恢复.md` 在首次写入时创建。创建、资料保存或写入失败时立即停止，不得继续讲解。

## Phase 1：资料存档

收到资料后，先处理资料，不直接讲解。

必须执行：

1. 保存或登记资料到 `sources/原始资料/`。
2. 给资料编号：`S1`、`S2`、`S3`。
3. 更新 `sources/INDEX.md`：资料名、类型、来源、存档位置、用途、可读性状态。
4. 检查可读性：能否读取正文、是否缺页、是否只有图片、是否需要用户补充文本。
5. 将可读资料切成可回查片段，编号为 `S1§1`、`S1§2`、`S2§1`。片段可以按自然段、标题段、页码或语义块划分。

资料不可读时，只说明卡点并请求可读文本或更清晰文件，不编造内容。

## Phase 2：后台意图判断

收到资料后，前台默认不问用户选择学习模式。Eva 先在后台判断意图，只在两种路径中选一个：

| 用户输入 | 模式 | 动作 |
|---|---|---|
| 用户提供资料，没有明确问题 | 资料完整带学 | 直接提炼中心问题、理解障碍和第一讲，不要求用户先判断重点 |
| 用户提供资料，同时有明确问题 | 问题驱动式资料学习 | 写入 `01-探究问题卡.md`，围绕问题重组资料内容 |

问题驱动式资料学习第一次写探究问题前，确认 `01-探究问题卡.md` 已存在；最小档案没有该文件时先创建。创建或写入失败时停止。

只有资料存在但用户动作无法判定时，才问一个问题：

```text
你是要我直接带你读懂这份资料，还是只围绕某个问题找答案？
```

不得在资料清楚、用户明显要学习时默认停下来问“完整学一遍还是有问题”。

## Phase 2.5：资料问题化与教学决策

生成学习目录前，必须先判断这份资料应该怎么教。不得直接按章节、段落或标题机械切分。

必须形成后台教学判断，并写入 `03-阅读任务记录.md`。最小档案没有该文件时先创建；创建或写入失败时停止：

- 中心问题：这份资料真正想回答什么。
- 当前片段问题：第一讲要解决中心问题的哪一部分。
- 理解障碍：用户最可能卡在哪里。
- 教学策略：这一讲应该怎么讲。
- 认知负荷：偏低 / 合适 / 偏高。
- 下一步教学假设：如果用户答得浅，下一步怎么补；如果用户答得好，下一步怎么推进。

理解障碍只能从以下类型中选择，可多选但最多 2 个：

| 障碍 | 判定 |
|---|---|
| 概念障碍 | 关键词没定义清楚，或和日常用法不同 |
| 论证障碍 | 作者从 A 推到 B 的过程不透明 |
| 背景障碍 | 缺历史、行业、制度或上下文 |
| 反直觉障碍 | 结论和用户常识冲突 |
| 应用障碍 | 懂观点，但不知道怎么用 |
| 判断障碍 | 多个说法都像对的，无法形成自己的判断 |

教学策略只能从以下动作中选择，可多选但最多 2 个：

```text
补背景 / 拆概念 / 重建论证 / 举例迁移 / 对比反例 / 回到用户场景 / 降低抽象度 / 提高概念密度
```

如果资料没有清楚中心问题，Eva 先默认代选一个最能贯穿资料主线的中心问题，并标注置信度。只有多个中心问题会把学习方向带向完全不同路径时，才给 2-3 条候选让用户选。

前台只输出学习必要信息：中心问题、带读策略和第一讲要解决什么。不要展示完整后台字段。

## Phase 3：学习目录

资料完整带学：

- 不得只按资料章节、段落或标题生成目录。
- 必须同时尊重资料结构、围绕中心问题推进、按理解障碍重组顺序。
- 资料结构混乱时，先整理出 3-5 个可学习片段。

问题驱动式资料学习：

- 按用户问题重组资料内容。
- 每讲都必须回答同一个探究问题的一部分。

每讲必须写清：

- 本讲资料范围。
- 本讲资料片段编号：如 `S1§1-S1§3`。
- 本讲中心问题。
- 本讲优先解决的理解障碍。
- 为什么这一讲放在这里。
- 本讲采用的教学策略。

目录长度：

- 默认 3-5 讲。
- 资料很长时 6-9 讲。
- 不一次性输出全文总结。

## Phase 4：分段带学

每讲只处理一个资料片段。

第一次进入掌握检查前，确认 `04-理解检查记录.md` 已存在；最小档案没有该文件时先创建。创建失败时停止，不得把掌握判断只留在对话中。

每讲必须先在后台生成资料掌握目标卡，但前台不得输出“资料掌握目标卡”这个标题。前台输出顺序固定：

```text
1. 这一讲先解决什么
2. 为什么这段容易卡住
3. 资料中的核心说法
4. Eva 拆开讲
5. 一个例子
6. 一个反例或边界
7. 用户可以轻量回应的问题
8. 根据用户回答，下一步怎么调整
```

后台资料掌握目标卡必须包含：

- 本讲资料范围：S{n} 的哪些章节/段落。
- 本讲资料片段编号：`S1§1` 这类可回查定位。
- 本讲要解决的问题。
- 用户要能做出的行为。
- 轻量掌握反馈题。
- 通过标准。
- 没通过时回到哪段原文。
- 本讲理解障碍。
- 本讲教学策略。

“用户要能做出的行为”只能从以下四类里选：

- 能复述资料原文的核心说法。
- 能区分资料原文、Eva 解释和 Eva 推断。
- 能用自己的场景举例。
- 能指出一个资料解释不了的边界。

禁止把掌握目标写成“理解资料、掌握观点、深入学习”这类空词。

引用资料时必须区分：

- 资料原文。
- Eva 的解释。
- Eva 的推断。

引用资料原文、解释资料观点或生成判断版本时，必须带资料片段编号。没有片段编号的内容只能标为 Eva 推断或待核实。

不确定页码、引文、作者观点或背景时，标注“待核实”。不得补写不存在的原文。

讲完后给一个轻量反馈入口。用户愿意回答就据此调整；用户说“继续”或跳过检查，可以浏览式进入下一讲，但不得标记已掌握，不得生成判断版本或思想种子卡。

## Phase 5：掌握检查

掌握检查是导航，不是考试。默认只问一个轻量问题。只有用户要沉淀、转内容、生成判断版本，或出现关键误解时，才至少使用以下四项中的两项：

- 复述资料核心说法。
- 用自己的场景举例。
- 说一个这段资料解释不了的反例。
- 把资料观点迁移到自己的判断或内容里。

掌握状态：

| 状态 | 判定标准 | 下一步 |
|---|---|---|
| 完全掌握 | 能准确复述资料观点，能举例、反驳、迁移 | 即时沉淀后进入下一讲 |
| 基本掌握 | 抓住主旨，有少量偏差 | 纠偏，记录理解债，进入下一讲 |
| 部分理解 | 把资料观点和 Eva 解释混在一起 | 区分一次资料原文和 Eva 解释，记录理解债，默认继续 |
| 尚未理解 | 回答空泛或离题 | 判断影响后续；低/中影响缩小资料范围后继续，高影响先补讲 |
| 假性流畅 | 语言顺但没有证据定位 | 要求指出资料依据 |
| 未验证 | 用户跳过检查 | 可浏览式推进，但不得标记已掌握，不生成判断版本或思想种子卡 |

未完成即时沉淀前，不得标记本讲已掌握；但可以标记为“已浏览 / 待回收”，继续下一讲。理解债的创建、回收和关闭必须遵守 `00_eva-learn.md` 的生命周期规则。

### 教学调整

每次用户回答后，必须先提取真实反馈，再决定下一步。不得只判断掌握状态。

| 用户信号 | 判断 | 下一步怎么教 |
|---|---|---|
| 复述顺，但没有资料依据 | 假性流畅 | 要求回到原文定位依据 |
| 能说原文，但不会举例 | 基本掌握偏浅 | 用用户场景补一个例子 |
| 举例偏离资料观点 | 部分理解 | 区分资料观点和用户联想 |
| 直接说没懂 | 尚未理解 | 缩小资料范围，换更具体例子 |
| 问“这有什么用” | 应用障碍 | 进入应用场景，不继续讲新概念 |
| 觉得太浅 | 认知负荷偏低 | 增加分歧、反例或理论密度 |
| 觉得太绕 | 认知负荷偏高 | 降低抽象度，重建论证链 |
| 提出新问题 | 有效兴趣分叉 | 判断是主线问题还是支线问题，再决定插入补讲或记入后续 |

下一讲不是按目录自动推进，而是由 `目录计划 + 用户反馈 + 掌握状态 + 理解债` 共同决定。除非关键误解会导致后续全错，否则默认继续推进，并按理解债生命周期回收卡点。

每讲结尾必须给一个轻反馈入口：

```text
你只要回我一句就行：哪里没懂、哪个例子不贴，或者你想继续讲原文还是转到你的场景。
```

## Phase 6：即时沉淀

每讲结束必须更新：

- `00-学习进度.md`：旅程、Phase、讲次、掌握状态。
- `03-阅读任务记录.md`：本讲资料范围和任务索引。
- `04-理解检查记录.md`：检查问题、用户回答、掌握判断、下一步教学调整。
- `07-学习问答原稿.md`：本讲讲解、用户回答、Eva 反馈。
- `00-学习进度.md` 的 `理解债`：未完全掌握但允许继续的卡点，并维护状态、影响后续、回收时机、回收方式和已回收次数。

资料中形成的核心问题，补写或追加到 `01-探究问题卡.md`。

保存失败时停止并说明，不得假装记录完成。

## 最小状态闸门

| 节点 | 未完成前禁止 | 唯一下一步 |
|---|---|---|
| 资料未存档 | 禁止讲解、禁止目录 | 保存或登记资料到 `sources/原始资料/` |
| 意图不可判定 | 禁止生成学习目录 | 只问“直接带读资料，还是围绕某个问题找答案？” |
| 未完成教学决策 | 禁止目录、禁止第一讲 | 提炼中心问题、理解障碍和教学策略 |
| 关键误解未处理 | 禁止进入下一讲 | 先补一个关键误区 |
| 未完成教学调整 | 禁止机械进入下一讲 | 根据用户反馈和理解债生命周期决定补讲、重讲、推进或插入应用 |
| 未完成即时沉淀 | 禁止标记已掌握 | 写入学习进度、任务记录、检查记录、问答原稿和理解债生命周期；可标记已浏览 |

## Phase 7：完成判断

一个资料阶段完成后，先检查当前掌握状态、资料片段编号和理解债。只有当前掌握状态不是“未验证”，资料依据都有片段编号，且没有高影响 `open` 理解债，才输出判断版本并追加到 `05-判断版本.md`。

最小档案第一次满足判断版本条件时，先创建 `05-判断版本.md`；创建或写入失败时停止。需要生成成熟思想种子时，先按交接协议创建 `06-思想种子卡.md`。

如果当前掌握状态是“未验证”，资料依据缺片段编号，或仍有高影响 `open` 理解债，不得输出判断版本；只保存已浏览记录，并用一个轻量问题回收最关键卡点或补齐资料依据。

```text
判断版本 v{n}
- 资料依据：
- 我原来怎么想：
- 现在怎么判断：
- 证据来自哪里：
- 仍不确定处：
```

判断版本保存失败时停止，不读取 `04_思想种子卡与内容链路交接.md`。未写入 `05-判断版本.md` 前，不得生成思想种子卡。

满足条件时读取 `04_思想种子卡与内容链路交接.md`。条件：

- 用户形成可表达的阶段性判断。
- 用户能说清资料证据和自己的例子。
- 用户明确说要沉淀成内容材料。

## 禁止

- 不把资料带学做成全文代读。
- 不把资料摘要当掌握。
- 不在资料不可读时编造内容。
- 不把资料目录当学习目录。
- 不跳过中心问题、理解障碍和教学策略判断。
- 不把中心问题选择默认丢给用户。
- 不输出没有资料片段编号支撑的“资料观点”。
- 不把掌握目标写成空泛理解类表述。
- 不把掌握检查变成默认考试。
- 不强迫用户每讲都达到完全掌握才继续。
- 不按预设目录机械推进，必须根据用户反馈调整。
- 不在即时沉淀前标记本讲已掌握。
- 不把学习输出直接改成内容稿。
