# Commerce 01：Brief 基础解析

本文件只把 Brief 原文拆清楚：产品、硬要求、卖点池、风险和缺口。它不筛选主讲卖点，不生成正式商单约束卡，不检查已有稿。

## 输入

- 品牌 Brief 原文。
- 产品名、产品介绍、卖点表。
- 必提信息和禁止信息。
- 交付要求、平台、时长、字数、口播要求。
- 活动信息、口令、链接、行动指令。
- 品牌给出的参考样例。

如果只有产品名和几个卖点，没有正式 Brief，允许低置信度拆解，但不得输出正式商单约束卡。

## Phase 1：Brief 基础解析

先从原文提取：

- 产品：
- 品类：
- 核心功能：
- 目标人群：
- 使用场景：
- 品牌目标：
- 必提信息：
- 禁止信息：
- 交付要求：
- 平台要求：
- 行动指令：
- 时间节点：
- 品牌给出的参考样例：

输出时必须区分“Brief 原文明确写了”和“模型推断”。

如果某项是推断，标注“推断-待确认”。

## Phase 2：品牌硬要求锁定

把 Brief 里的要求分成三类：

| 类型 | 判断标准 | 处理 |
|---|---|---|
| 必须原样保留 | 品牌名、产品名、活动名、口令、合规话术、指定功能名 | 不改写，不删 |
| 可以转述 | 功能解释、使用场景、用户收益、品牌希望强调的态度 | 可转成用户听得懂的话 |
| 禁止触碰 | 不能说的功效、不能承诺的数据、不能拉踩竞品、不能涉及的词 | 明确避开 |

不要把“可以转述”的内容误判成“可以删除”。

不要把“品牌想强调”的内容误判成“必须全文原样照读”。

## Phase 3：卖点池拆解

把 Brief 里的全部卖点拆成表格：

```markdown
## 卖点池

| 卖点 | 解决的问题 | 适合场景 | 所需真实素材 | 表达风险 | 是否必提 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |
```

判断标准：

- 它解决的是用户哪个具体问题？
- 它适合出现在什么生活、学习、工作或创作场景？
- 它需要学员有什么真实经历或使用感受支撑？
- 它是否容易被讲成夸大承诺？
- 它是否是品牌必提，还是可选卖点？

如果一个卖点只能靠编造经历才能讲，不推荐主讲。

如果一个卖点很重要但缺真实体验，标注 `[待补充真实使用感受]`。

## 低置信度拆解

如果没有正式 Brief，只能输出：

```markdown
## 低置信度卖点拆解

- 产品：
- 已知卖点：
- 可能用户场景：
- 待确认品牌必提：
- 待确认品牌禁忌：
- 待确认交付要求：

## 下一步补充清单

1.
2.
3.
```

低置信度拆解的边界：

- 不输出正式商单约束卡。
- 不推荐直接接 `/eva-script`。
- 如果缺少品牌必提信息和禁止信息，不做主讲卖点最终筛选。

## 输出

```markdown
## Brief 需求拆解

- 产品：
- 品类：
- 核心功能：
- 目标人群：
- 品牌目标：
- 必提信息：
- 禁止信息：
- 交付要求：
- 行动指令：

## 品牌硬要求

| 内容 | 类型 | 处理方式 | 风险 |
|---|---|---|---|

## 卖点池

| 卖点 | 解决的问题 | 适合场景 | 所需真实素材 | 表达风险 | 是否必提 |
|---|---|---|---|---|---|
```
