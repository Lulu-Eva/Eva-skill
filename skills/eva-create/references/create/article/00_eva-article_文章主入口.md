# Eva Article：文章主入口

Article 是 Eva Create 内部的非虚构自媒体文章分支，不是新的顶层 Skill。它负责判断文章任务、材料是否足够，以及该直接成稿、只问一个问题，还是退出 Article。

## 进入边界

进入 Article：

- 写一篇公众号文章、自媒体文章、观点长文或非虚构短文。
- 把想法、课程资料、思考记录或已成熟判断整理成文章。
- 续写、局部修改、结构重排或完整重写已有文章。
- 用户显式调用 Eva Create，并且最终要的产物是上述文章。

不进入 Article：

- 朋友圈、微博、小红书短图文、邮件、普通商务文案或其他短文案。
- 小说、诗歌、剧本等虚构或纯文学创作。
- 学术论文、技术文档、投标文件、法律文书、医疗报告等专业写作。
- 只检查 AI 味或表达真实性，且用户明确不要改稿。
- 只拆解他人样本，且用户明确不要创作新文章。
- 正式品牌商单、有必提卖点、禁区或品牌承诺的赞助文章。首版先转 `eva-brief` 形成真实约束，不在 Article 内直接完成商单成稿。

最终输出形式优先于输入材料形式：短视频稿可以被重写成文章，长文章也可以被转成短视频。不得只看材料原本长什么样就决定路由。

## 任务分流

| 用户目标 | 当前动作 |
|---|---|
| 信息充分，要完整文章 | 同一轮读取论证路线和撰写协议，直接交付完整文章 |
| 缺少一个会改变中心判断的信息 | 说明当前能确定什么，最多只问一个关键问题 |
| 只要大纲 | 读取论证路线，只输出读者问题与推进顺序 |
| 局部修改 | 只读取与授权范围有关的部分，不改其他段落 |
| 续写 | 保留已有中心判断、事实层级和声音，从中断处继续 |
| 完整重写 | 只在用户明确授权时重建论证和全文 |

## 信息充分判断

用户不需要填表。后台只检查三件事：

1. 这篇文章要让读者对什么产生新理解。
2. 现有经历、事实、机制解释或材料能否支撑这个判断。
3. 用户对长度、文风、修改范围或 CTA 是否有必须遵守的要求。

上下文已经能回答时，不重复追问。读者可以从具体处境和疑问推断，不要强迫用户先报人口标签。只有一个缺口会让文章走向完全不同时才问；不把字数、平台栏目名或工作标题当成必问项。

信息充分且用户明确要全文时，同一轮直接交付完整文章；不先让用户确认大纲，不用空问题延迟成稿。

“AI 改变了创作”“开源很重要”这类只是宽泛主题，不是核心判断。用户只给宽泛主题，没有给出作者立场、具体读者问题、亲历/材料或明确的解释目标时，必须判定为关键信息不足。不得由 Article 自行挑一个泛化观点，再用模型常识把它扩成一篇看似完整的文章。

这种情况只问一个能决定文章方向的问题，例如：

```text
你希望读者读完后，对“AI 改变创作”形成哪一个与你有关的具体新判断？
```

## 执行顺序

```text
确认属于 Article
-> 判断任务是新写、续写、局部修改、重写还是大纲
-> 信息足够时读取 01 观点与论证路线
-> 需要成稿时继续读取 02 文章撰写与长度调节
-> 同一轮输出用户要的产物
```

标题不是文章成稿前的硬闸门。先让核心判断和正文成立，再用标题概括已被正文兑现的承诺。

## 不编造边界

- 不补造用户经历、对话、评论、案例、引用、数据、产品动作或第三方意图。
- 时效事实、数据或准确引用对结论重要时，有可靠检索能力则核验；当前无法核验时删去、降格为明确的个人判断，或保留 `[待核验]`。
- 不把“我认为”写成已证实规律，也不因为无法核验就把作者立场磨平。
- 用户自有产品或社群的 CTA 可以写；未提供价值、对象或加入方式时，只问一个问题或标记 `[待补]`，不发明价格、名额、截止时间和效果承诺。

## 输出边界

- 信息充分且用户要全文：前台直接交付推荐标题和完整文章，不展示内部分类、检查表或路由过程。
- 只要大纲：只交付读者问题与论证顺序。
- 只改局部：默认只交付改后部分，需要上下文时仅补最小对照。
- 确有事实或 CTA 缺口时，在文后单列“待核验 / 待补”；没有缺口时不为了显得严谨而加空栏。

## 保存与交接

默认不保存文章、样本或文风。用户明确说保存、沉淀或下次继续时，再读取 `asset-types.json` 和 Asset 协议，复用 `content-task-card` 或 `content-asset-card`。不新增 Article 专用资产类型，不自动沉淀长期文风。
