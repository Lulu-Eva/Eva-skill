# Eva Article 01：观点与论证路线

本文件只负责建立读者任务、核心判断、材料层级和论证路线。它不选固定模板，不负责最终文风、字数、标题或 CTA。

## 1. 读者任务

先把文章压缩成一句后台判断：

```text
这篇文章要让「处在什么情境、正在困惑什么的读者」
从「原来的理解」走到「新的理解」。
```

- 优先使用用户已经给出的处境、疑问和目标，不要重复询问“年龄、城市、性别”等对当前论证无影响的标签。
- 有已确认的 `audience-card` 可以复用；没有时用当前语境做轻量判断，不为 Article 新建第二套人群资产。
- 如果两种读者处境会导向两个完全不同的中心判断，返回主入口，只问一个能区分它们的问题。

## 2. 核心判断

核心判断不是“我想聊 AI”这种主题，而是读者读完后可以接受、反对或修正的一句话。

这一句必须来自用户原话、上下文已形成的判断、用户明确要解释的问题，或一个经用户确认的推断。不得仅凭宽泛主题，由 Article 替用户选一个有传播感的观点。

检查：

- 它是否回答了读者的真实疑问，而不只是作者想表态。
- 它是否比常识多了一层可解释的机制、因果或边界。
- 它是否被材料支撑，而不是只靠更强的形容词。
- 它是否可以保留锋利程度，同时不伪装成已证实事实。

一篇文章默认只服务一个中心判断。其他观点只在支撑、限定或延伸中心判断时保留。

## 3. 材料与证据分层

成稿前在后台区分四类：

| 层级 | 含义 | 使用规则 |
|---|---|---|
| 亲历 | 用户明确提供的个人经历、感受和可回忆场景 | 可用第一人称，但不补造细节 |
| 事实 | 可被第三方核验的数据、引用、产品动作和外部事件 | 核验、标记 `[待核验]`，或删去；不伪造来源 |
| 推论 | 作者对原因、趋势、影响和机制的解释 | 保留为作者判断，写清依据与限定 |
| 修辞 | “战争结束了”这类为传播强度服务的概括 | 可以强，但正文必须让读者看出它是立场或比喻 |

不要仅因为一句话“听起来对”就提升它的证据等级。不要为让文章更完整而生成虚构调研、专家话语、读者留言或成功案例。

## 4. 读者追问链

核心判断成立后，只保留读者真正需要的追问：

```text
你说的问题具体是什么？
-> 为什么会这样？
-> 你的材料能证明到哪一步？
-> 最强的反对意见或适用边界是什么？
-> 读者现在应该如何重新理解或行动？
```

不是每篇都要回答五个问题。删去对读者认知转变没有贡献的问题，直到剩下最短闭环论证路径。

## 5. 组织论证关系

按当前材料选关系，不让用户先选文章模板。可用关系包括：

- 冲突 -> 机制 -> 结果 -> 延伸判断。
- 现象 -> 核心变量 -> 代价 -> 行动。
- 经历 -> 发现 -> 解释 -> 适用边界。
- 观点 -> 反对意见 -> 回应 -> 收束。
- 问题 -> 多种解释 -> 核心变量 -> 新判断。

这些是逻辑关系，不是固定段数。可以混合，也可以只用两步。反对意见只在它会改变结论强度时展开，不为了显得客观而虚构一个假想敌。

## 6. 进入撰写的最低条件

- 中心判断基本清楚。
- 可以判断读者的处境或疑问。
- 至少有一条能支撑判断的亲历、事实、机制解释或证据路径。
- 未核验的事实已被标出，不需要靠编造才能补齐。
- 论证的每个关键跳跃都有机制、材料或明确的不确定性承接。

条件成立时，交给 `02_eva-article-writing_文章撰写与长度调节.md`。不在前台默认展示读者任务、材料表和追问链；用户只要大纲时，才把追问与推进顺序转成可读大纲。
