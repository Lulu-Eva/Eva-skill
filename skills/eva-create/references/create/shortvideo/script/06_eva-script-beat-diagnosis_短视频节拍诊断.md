# Eva-skill 短视频节拍诊断

本文件只在用户已经提供短视频稿，并明确要求检查节拍、水分或推进时读取。先读取 `../01_eva-beats_短视频节拍与心智推进.md`；本文件只控制诊断怎样交付，不维护第二套节拍定义。

## 默认交付

```markdown
## 关键判断

用白话说明一个最高优先级问题；确属节拍问题时，最多附一个轻量标签：（停拍）/（复拍）/（跳拍）/（挤拍）。

## 原文证据

只指出最能证明该判断的一处原文。

## 实际影响

说明它怎样影响理解、承诺兑现或口播推进。
```

- 不默认展示完整节拍链、分类表、评分或修改稿。
- 实际问题是理解门槛、代入、情绪、节奏、转场、口播或用户文风时，用白话说明真实问题，不强贴节拍标签。
- 用户说“只诊断、不要改”时，交付上述结果后立即停止，不给调整方向、下一步或续轮邀请。
- 用户明确问“怎么调、给建议”时，才在结果后增加一个调整原则，不直接改稿。
- 用户明确要求修改时，才返回现有 Writing 链路，并继续服从标题、Brief、事实与路线硬闸门。
- 只有用户明确要求“列出节拍链、逐拍拆解、按四类分类”时，才展开节拍链；仍只保留一个最高优先级问题。
- 短视频同时要求 AI 味与水分检查时，除非用户明确说“只看节拍”，否则由表达真实性审查统筹。
- 用户要求完整发布总检时转 Eva Preflight；本文件不输出发布三档。
