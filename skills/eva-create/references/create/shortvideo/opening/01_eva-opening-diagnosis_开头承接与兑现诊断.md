# Eva-skill 开头承接与兑现诊断

本文件是 Opening 的唯一诊断真源。它只判断现有开头、用户材料和后文承诺能否支撑优化，不生成新开头，不改写原稿。

## 诊断输入

根据当前任务只取必要信息：

- 目标平台，以及是否依赖封面/标题点击。
- 有标题时：封面标题、正文标题、标题疑问与已有验证状态。
- 原第一句、前三句，以及能判断后文兑现的最小正文。
- 这条内容讲给谁、要回答什么、后文真正能给出什么。
- 若为商单：已确认的必提、禁区、不可承诺和可用真实素材。

用户只要局部优化时，不强制补完整正文或交接卡；但至少必须知道后文能兑现什么。缺少时只问一个问题。

## 一、生成前硬闸门

硬闸门的优先级高于开头技巧。先完成以下检查，再判断是否允许生成。

### 1. 商单 Brief 与约束

- 已出现品牌合作、必提、禁区、卖点、不可承诺或交付要求，但没有合格商单约束：`材料放行：返回上游`。
- 商单约束完整时，将必提、禁区、不可承诺和可用素材作为开头生成的硬边界。
- 不得为了开头更强，新增效果承诺、使用体验、价格优势或品牌未确认口径。

### 2. 平台与标题链路

| 场景 | 诊断主路径 | 不可绕过 |
|---|---|---|
| 小红书等标题点击场景 | 标题疑问 -> 第一句打开小口 -> 前三句承接 -> 正文兑现 | 标题验证状态 |
| 抖音、视频号等无标题场景 | 第一句建立话题、停留理由和兑现线索 -> 前三句 -> 正文 | 不强制标题验证 |

- 小红书标题没有验证线索，且未按既有低置信度协议获得用户授权时：`材料放行：返回上游`，回 `/eva-title`。
- 有标题时，第一句不必重复标题全部信息，但必须立即回应标题制造的同一个疑问。
- 平台不明且会改变主路径时：`材料放行：仅诊断`，只问小红书还是抖音/视频号。

### 3. 事实与承诺边界

内部建立一份“可用事实边界”，不默认向用户展示字段表：

```text
已确认可用：用户明确提供，且未与其他材料冲突
待确认：材料出现但口径、归因或精度不清
不可使用：用户未提供、与材料冲突，或被 Brief 明确禁止
```

重点核对：

- 人物身份、经历、角色与第一人称资格。
- 时间、数字、比例、结果、Offer、收入、效果和比较级。
- “因为 A 所以 B”、“真正拉开差距的是 A”等因果或归因。
- “2 分钟教会”、“手把手”、“模板全部给你”、“不需要任何经验”等方法、时长或教程承诺。
- 评论区原话、高赞、对标来源和平台反馈。

边界规则：

- 不得升级结果或范围；单一个案例不得改成对所有人都成立的结论。
- 时间先后或相关性不等于因果。
- 待确认信息如果可以完全删去而不改变这条内容的主承诺，可以降级为只使用已确认事实；如果主承诺依赖待确认信息，则不允许生成。
- 要求编造数据、经历、结果、评论或因果时：`材料放行：返回上游`。

### 4. 后文兑现能力

满足以下任一条，才可判断开头能否优化：

1. 有完整正文。
2. 有已成立的标题交接或第一句话交接。
3. 有核心判断 + 至少 1 个真实素材。
4. 有话题 + 用户处境 + 后文要回答的问题。
5. 有足以判断承诺的原稿片段。

全部不满足时：`材料放行：仅诊断`。不得因为用户想要灵感就生成没有后文可兑现的空钩子。

## 二、开头诊断标准

诊断顺序固定为：事实与承诺安全 -> 原意、叙述视角和事实颗粒度忠实 -> 正文能够兑现 -> 口播自然。节拍只在这些判断都成立后用于发现推进问题，不能为了第一拍更清楚而改写用户原意。

- 原开头已经成立时，优先保留或做最小修改，不为展示技巧而换掉。
- 不把可观察事实改写成心理状态、咨询意图或用户未提供的动机。
- 不擅自改变“我 / 你 / 她”等叙述视角，也不把时间先后升级成因果。

### 有标题开头

依次判断：

1. 第一句是否承接标题的主疑问，而不是开一个新话题。
2. 是否只复述标题，没有打开一个小口。
3. 第一句新增的情绪、结果、反差或方法承诺，正文是否能兑现。
4. 前三句是否连续把用户从标题带入正文。

### 无标题第一句

第一句必须尽量同时建立：

```text
这条在讲什么
为什么现在继续听
后面真正能兑现什么
```

三项缺少任一项，都记为当前开头问题；但只要后文承诺与事实边界清楚，仍可放行到生成文件修正。

### 第一拍与前三句承接

前三句共同负责启动或完成第一拍，不要求每一句各自形成一拍。第一句要确认话题入口；后续句子按当前材料补足必要的解释、预期、场景、证据、动作或转场，让用户从起点理解走到一个清楚的新位置。开头可能一句完成第一拍，也可能需要三句共同完成。

具体的节拍、支撑和停拍 / 复拍 / 跳拍 / 挤拍判断只读取 `../01_eva-beats_短视频节拍与心智推进.md`，本文件不另建句数规则。连续语句既没有完成当前推进、也没有提供必要支撑时，才记为开头推进问题。

前三句还要做一次软功能覆盖检查。功能可以由一句完成，也可以跨两三句共同完成；不固定句序，不要求正好三句：

- **入口与停留**：用户能确认在讲什么，并获得继续听的理由。
- **解释与澄清**：开头真正打开内容，而不是换词复述标题或上一句。
- **回报与兑现线索**：给出真实回报，或留下正文马上会回答的下一个有效缺口。

这不是“第一句一拍、第二句一拍、第三句一拍”。软功能低于事实、Brief、标题对位和正文兑现；一句已经完成时不补句，三句只是重复时仍判为问题。

### 可感知落点软检查

- 观点、故事或个人表达的前三句连续停留在抽象判断，而现有材料已经包含具体处境、动作、对话、证据或可观察变化却没有使用时，按节拍真源标记为当前第一拍缺少可感知支撑。
- 教程或解释型内容可以用明确答案、具体动作、真实收益或可观察区别作为落点，不强制讲故事、增加情绪或制造转折。
- 现有材料没有可感知落点时，不编造场景、对话、证据或结果，不增加追问，也不把这项软检查升级为生成阻塞；只压缩抽象表达，保留已经成立的承诺与判断。
- 这项检查低于事实、Brief、标题承诺和正文兑现；开头已经清楚成立时，不为了增加画面感而强行改写。

### 现有关注入口软检查

后台只问：**当前材料是否已经包含真实的情绪张力或公共关注入口？如果有，它能否帮助正确的人更快进入主问题，并由正文真实兑现？**

- **真实情绪张力**必须来自用户已经提供的经历、处境、选择、压力或尚未解决的矛盾；它不是增加愤怒、焦虑、敌人、身份冲突或更强烈的情绪词。
- **公共关注入口**必须来自用户提供或已经确认的话题、现象与公共语言；没有可靠材料时，不声称“正在爆”“全网都在讨论”，也不自动联网、追逐实时热点或猜测平台趋势。
- 只有它仍然服务既定具体人群、进入同一个主问题，并且正文能够解释其意义或回答真实缺口时，才允许作为现有开头机制的素材力量使用。
- 没有、无关或无法验证时直接忽略：不追问、不阻塞、不降低温和经历、教程、信息解释或普通观点的质量判断，也不把它升级为情绪门槛或传播预测。

### 常见问题

- 事实结果越级：材料只说“收到面试邀请”，开头却写成“拿到 Offer”。
- 因果越级：材料只呈现“做了作品集，之后收到面试”，开头却写成“作品集让她拿到面试”。
- 承诺越级：Brief 或正文没有对应步骤、模板、时长和收益，开头却承诺“2 分钟教会”“模板全部给你”，或标题只承诺解释现象，开头却新增教程任务。

## 三、诊断结果

生产调用时，返回：

```markdown
## 开头诊断

- 场景：有标题开头 / 无标题第一句 / 只优化开头
- 开头判断：通过 / 存在问题 / 无法判断
- 最高优先级问题：
- 原文证据：
- 后文能兑现：
- 不可新增的事实或承诺：
- 材料放行：允许生成 / 仅诊断 / 返回上游
- 唯一下一步：
```

已经允许生成时，这份结果只是给 02 的执行依据；前台不必展开全部内部字段，只用一句话说明最高优先级问题。

不放行时，前台只说明：

```markdown
## 先别急着改开头

现在最先卡住的是：
因为：
先补这 1 个东西：
```

不给多个问题，不同时展开所有风险。

## Preflight 只读调用

只有 `eva-preflight` 已确认输入是基本成形、尚未发布的自然语言成稿时，才以只读方式调用本文件；以下规则覆盖生产调用的输出与下一步规则。

- 有标题场景检查“标题疑问 -> 第一句 -> 前三句 -> 正文”；完成该主路径后，才做无标题软韧性复核，不得绕过标题验证。
- 抖音、视频号直接以无标题第一句为主路径，不强制标题验证。
- 只返回 `通过 / 存在问题 / 无法判断`、问题位置或原文证据、影响原因、候选严重度和缺失材料。开头第一拍的节拍判断只读 `../01_eva-beats_短视频节拍与心智推进.md`。
- “第一拍可感知支撑不足”通常只作为优化建议；只有它已经导致入口说不清话题、回报或后文承诺时，才按对应的理解或兑现问题报告，不能单独触发“暂不建议发布”。
- 禁止读取 `02_eva-opening-generation_开头方案生成与推荐.md`；禁止生成或改写开头，禁止生成第一句话交接卡、资产或下一步生产跳转。
- 诊断结果交给 Preflight 05 统一汇总，最终三档结论归 Preflight 00。
