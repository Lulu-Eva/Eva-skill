# Eva Preflight 04：表达资产增强

本文件只负责把已加载的 persona-card / voice-card 映射为 Preflight 审核判断。扫描范围、多卡优先级、隐私、前台提示、状态和失败处理全部以 `../eva-shared/references/shared/05_expression-asset-preload_表达资产轻量预加载协议.md` 为唯一真源，本文件不复制第二套规则。

## 1. 进入条件

- 先确认稿件是用户本人或团队准备发布的稿件，再按 shared 05 扫描；第三方参考稿跳过本分支。
- shared 05 返回未扫描、未命中或不可用时，静默继续通用审核；不追问建卡，不得判断“不像用户本人”。
- 不对 Memory 的领域 Markdown 卡运行通用 Asset validator。

## 2. 人设映射

用已确认的 persona-card 字段判断：

- 稿件依赖的身份、经历或专长是否有现有事实支撑。
- 第一人称经历、成绩、职业资格、使用体验或效果是否与卡片明确事实直接冲突。
- 稿件是否越过已确认的身份事实或不可触碰边界。

话题超出账号惯常领域本身不等于错误，不得把 persona-card 变成“只能说固定话题”的限制器。卡片没有记录某段经历，不等于该经历不存在，只能标记 `[需确认]`；观点与历史立场不同也先视为可能的立场更新。

与已确认身份、经历、资格或禁区直接冲突，尤其涉及伪造第一人称经历时，可以候选为发布级阻塞。资料未记录、低置信度推断和一般话题偏离不得单独形成硬判定。

## 3. 文风映射

用已确认的 voice-card 字段判断：

- 用词、句式、口语程度、节奏、称呼、转折、读者距离和 CTA 是否与本轮任务一致。
- 是否出现卡片明确希望避免的报告腔、居高临下、空气句、套话或其他表达习惯。
- 平台、内容类型和本轮指令导致的变化是否合理。

文风一致不等于机械仿写。一般偏离只算优化建议；只有用户明确要求严格保持账号文风，或偏离已明显损害身份可信度时，才可升级为必须修改。低置信度 voice-card 不得单独形成发布级阻塞。

## 4. 向主控返回

```text
表达资产加载结果：原样承接 shared 05 的状态
人设一致性：通过 / 存在问题 / 无法判断
文风一致性：通过 / 存在问题 / 无法判断
问题证据：只写判断所需信息，不展开无关私密字段
候选严重度：发布级阻塞 / 必须修改 / 优化建议
```

只有偏离对发布判断有实际价值时，才让主控输出“人设与文风一致性”栏目。卡片只作为只读证据；不补写正文、不更新卡片、不生成新卡、不保存审核报告。
